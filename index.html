1. How the Architecture Works

Elegir el asistente de IA adecuado

Choosing the Right AI Assistant

El primer paso de este proyecto no fue escribir código, sino elegir qué IA era la más adecuada para interactuar con EcoStruxure Machine Expert. Cuando inicié este desarrollo, ChatGPT Desktop no ofrecía esa capacidad; Gemini solo la tenía en su línea de comandos o como extensión de VS Code, sin una aplicación de escritorio equivalente; y GitHub Copilot sigue atado a editores de código. Claude Desktop, en cambio, ya la ofrecía desde su propia aplicación de escritorio, con un énfasis particular en programación — precisamente el terreno de este proyecto.

The first step of this project was not writing code, but choosing which AI was best suited to interact with EcoStruxure Machine Expert. When I started this development, ChatGPT Desktop did not offer that capability; Gemini only had it in its command line or as a VS Code extension, without an equivalent desktop app; and GitHub Copilot remains tied to code editors. Claude Desktop, on the other hand, already offered it from its own desktop application, with a particular emphasis on programming — precisely the domain of this project.

Esa capacidad se llama ser cliente MCP: hablar el protocolo MCP (Model Context Protocol) que permite conectarse a servidores externos que ofrecen herramientas nuevas. Conviene no confundir dos piezas: Claude Desktop (no confundir con Claude Code) es la aplicación de escritorio de Claude, la IA escogida; el servidor MCP de este proyecto es un programa Python aparte (server.py) que Claude Desktop arranca al iniciarse. Ambos se hablan por el protocolo MCP, no comparten tecnología.

That capability is called being an MCP client: speaking the MCP (Model Context Protocol) protocol that allows connecting to external servers offering new tools. It is important not to confuse two pieces: Claude Desktop (not to be confused with Claude Code) is Claude's desktop app, the chosen AI; this project's MCP server is a separate Python program (server.py) that Claude Desktop starts upon launch. They talk via the MCP protocol and do not share technology.

Cómo Claude conoce las herramientas disponibles

How Claude Knows Available Tools

Al arrancar ese proceso, Claude Desktop y el servidor MCP hacen un intercambio inicial por el protocolo MCP: el servidor le comunica el catálogo completo de herramientas que ofrece — en este caso, las 90 descritas en el capítulo 2, cada una con su descripción, sus parámetros y qué puede fallar. Esto ocurre una vez, al principio de la sesión, no en cada petición: Claude no necesita volver a preguntar al servidor qué herramientas existen cada vez que el usuario escribe algo nuevo. Ya las conoce desde el arranque, igual que un ingeniero que ya se ha leído el manual antes de empezar a trabajar.

Upon starting that process, Claude Desktop and the MCP server make an initial exchange via the MCP protocol: the server communicates the complete catalog of tools it offers — in this case, the 90 described in chapter 2, each with its description, parameters, and potential failure modes. This happens once, at the beginning of the session, not on every request: Claude does not need to ask the server again what tools exist every time the user types something new. It already knows them from startup, just like an engineer who has read the manual before starting work.

Cuando el usuario escribe una petición, Claude decide, a partir de ese catálogo ya conocido, qué herramienta usar y con qué parámetros — sin ninguna consulta adicional: esa parte ya está resuelta de antemano.

When the user types a request, Claude decides, based on that already known catalog, which tool to use and with what parameters — without any additional query: that part is already resolved beforehand.

Por qué hace falta un JSON y un segundo programa

Why JSON and a Second Program Are Needed

Aquí aparece la restricción técnica que obliga a todo el diseño: el servidor MCP corre sobre una versión moderna de Python (CPython). Pero la API de Scripting de Machine Expert — la única forma soportada de automatizar el programa — solo funciona sobre IronPython 2.7, una implementación de Python bastante más antigua, pensada para integrarse con software .NET como el propio Machine Expert. El entorno de scripting de Machine Expert y la arquitectura de este proyecto no permiten resolver esa diferencia dentro de un mismo proceso: esto es una restricción de cómo está construida la integración entre ambos mundos.

Here appears the technical constraint forcing the entire design: the MCP server runs on a modern Python version (CPython). But Machine Expert's Scripting API — the only supported way to automate the program — only works on IronPython 2.7, a much older Python implementation designed to integrate with .NET software like Machine Expert itself. Machine Expert's scripting environment and this project's architecture do not allow resolving that difference within a single process: this is a constraint of how the integration between both worlds is built.

Es una situación parecida a la de dos departamentos de una misma empresa que hablan idiomas distintos y no pueden turnarse el mismo teléfono: necesitan a alguien en medio que traduzca cada mensaje. El JSON hace ese papel — es el idioma neutral que ambos entienden, aunque ninguno de los dos lo hable de forma nativa.

It is similar to two departments in the same company speaking different languages and unable to share the same phone: they need someone in the middle to translate each message. JSON plays that role — it is the neutral language both understand, even if neither speaks it natively.

Para quien no lo haya visto antes: JSON es simplemente una forma de escribir datos como texto, de manera que tanto una persona como un programa puedan leerlos sin ambigüedad. Una orden como "crea una variable BOOL llamada Motor_Ready" se escribiría en JSON como {"cmd": "create_variable", "name": "Motor_Ready", "type": "BOOL"} — nombres y valores, entre llaves, sin nada que interpretar de más. Es "universal" en el sentido de que prácticamente cualquier lenguaje de programación moderno sabe leerlo y escribirlo de forma nativa, lo que lo ha convertido en el formato por defecto para que programas distintos —aunque estén escritos en tecnologías incompatibles entre sí, como ocurre aquí— se intercambien información sin malentendidos.

For anyone who hasn't seen it before: JSON is simply a way to write data as text, so that both a person and a program can read it unambiguously. A command like "create a BOOL variable named Motor_Ready" would be written in JSON as {"cmd": "create_variable", "name": "Motor_Ready", "type": "BOOL"} — names and values, in curly braces, with nothing extra to interpret. It is "universal" in the sense that practically any modern programming language knows how to read and write it natively, making it the default format for different programs — even if written in incompatible technologies, as happens here — to exchange information without misunderstandings.

La solución es tener dos programas separados que se hablan por red, en vez de uno solo:

The solution is to have two separate programs talking over the network, instead of just one:

  • El servidor MCP (server.py, CPython) recibe la petición de Claude y decide qué acción ejecutar.
  • El bridge (bridge_host.py, IronPython), que se ejecuta dentro del propio proceso de Machine Expert. El usuario lo arranca una única vez, al principio de la sesión de trabajo, desde el menú Tools → Scripting → Execute Script File de la propia aplicación. A partir de ahí, el bridge abre un servidor de red local y queda escuchando en segundo plano — sin bloquear la interfaz, que sigue totalmente disponible para el usuario.
  • The MCP server (server.py, CPython) receives Claude's request and decides which action to execute.
  • The bridge (bridge_host.py, IronPython), which runs inside Machine Expert's own process. The user starts it once at the beginning of the working session from the application's Tools → Scripting → Execute Script File menu. From then on, the bridge opens a local network server and listens in the background — without blocking the UI, which remains fully available to the user.

Como ambos programas no pueden compartir memoria directamente (son procesos distintos, en versiones de Python distintas), se comunican enviándose mensajes de texto estructurado: JSON. Es un formato neutral que cualquiera de los dos puede leer y escribir sin depender de estructuras internas de Python que no son compatibles entre versiones.

Since both programs cannot share memory directly (they are separate processes in different Python versions), they communicate by sending structured text messages: JSON. It is a neutral format that either can read and write without depending on internal Python structures that are incompatible across versions.

NOTA IMPORTANTE
IMPORTANT NOTE
Este es el punto que más conviene tener claro: el protocolo MCP conecta a Claude únicamente con el servidor MCP — no llega hasta Machine Expert. El tramo entre el servidor MCP y el bridge es un canal completamente distinto, construido a medida para este proyecto, que no tiene nada que ver con MCP. This is the point most worth keeping clear: the MCP protocol connects Claude exclusively to the MCP server — it does not reach Machine Expert. The leg between the MCP server and the bridge is a completely different channel, custom-built for this project, which has nothing to do with MCP.

Qué ocurre dentro de Machine Expert al recibir la orden

What Happens Inside Machine Expert Upon Receiving the Command

El bridge recibe el JSON por ese canal de red, identifica qué orden se está solicitando gracias a un registro interno de comandos que la relaciona con una función concreta de la API de Scripting real de Machine Expert. El bridge localiza la función correspondiente y la ejecuta sobre el proyecto que el usuario tiene abierto en ese momento — el mismo proyecto, en la misma ventana, no una copia ni una simulación en segundo plano.

The bridge receives the JSON through that network channel, identifies which command is being requested thanks to an internal command registry relating it to a specific function in Machine Expert's real Scripting API. The bridge locates the corresponding function and executes it on the project the user currently has open — the same project, in the same window, not a copy or background simulation.

Un detalle técnico real que vale la pena mencionar, porque explica por qué todo esto es visible en tiempo real sin que la interfaz se congele: las operaciones que tocan la parte visual de Machine Expert (crear un elemento nuevo en el árbol de proyecto, por ejemplo) tienen que ejecutarse específicamente en el hilo principal de la interfaz gráfica — una exigencia estándar de las aplicaciones Windows, no algo propio de Machine Expert. Cualquier programa que quiera tocar la pantalla desde otro punto del código tiene que pasar por ese mismo hilo, o arriesgarse a un fallo. El bridge se encarga de enviar esas operaciones a ese hilo correctamente; si no se hiciera así, la aplicación podría bloquearse o fallar de forma imprevisible justo en el peor momento: a mitad de una operación sobre el proyecto real.

A real technical detail worth mentioning, because it explains why all this is visible in real time without freezing the interface: operations touching Machine Expert's visual part (such as creating a new element in the project tree) must execute specifically on the main graphical interface thread — a standard requirement of Windows applications, not something specific to Machine Expert. Any program wanting to touch the screen from another point in the code must go through that same thread or risk a failure. The bridge handles routing those operations to that thread correctly; otherwise, the application could lock up or fail unpredictably right at the worst moment: midway through an operation on the real project.

Es también la razón por la que este enfoque resulta especialmente exigente en proyectos complejos: cuantos más elementos tiene un proyecto — ejes, servodrives, módulos de E/S — más operaciones de este tipo se encadenan en una sola petición, y más importa que cada una se ejecute en el orden y el hilo correctos.

It is also why this approach is particularly demanding in complex projects: the more elements a project has — axes, servo drives, I/O modules — the more such operations chain together in a single request, and the more critical it is that each executes in the correct order and thread.

El camino de vuelta

The Return Journey

Una vez ejecutada la acción, el bridge construye la respuesta (qué se ha creado, qué valor tiene un parámetro, o el motivo por el que algo no fue posible), la convierte de nuevo a JSON, y la devuelve por el mismo canal de red al servidor MCP. El servidor MCP se la entrega a Claude por el protocolo MCP, y Claude la interpreta y responde al usuario en lenguaje natural — confirmando lo hecho o explicando con claridad qué ha fallado y por qué.

Once the action is executed, the bridge builds the response (what was created, what a parameter's value is, or why something wasn't possible), converts it back to JSON, and returns it over the same network channel to the MCP server. The MCP server delivers it to Claude via the MCP protocol, and Claude interprets it and responds to the user in natural language — confirming what was done or clearly explaining what failed and why.

Un apunte sobre dónde vive cada dato, relevante para cualquiera que se lo pregunte desde IT: el canal entre el servidor MCP y el bridge —el que lee y modifica el proyecto de Machine Expert— es 100% local, sobre la misma máquina, sin salir a ninguna red externa. Lo que sí ocurre, como en cualquier uso de Claude, es que la conversación con el modelo (incluidas las peticiones del usuario y los resultados que las herramientas devuelven) viaja a la infraestructura de Anthropic para que Claude pueda razonar sobre ella y responder — esto no es una particularidad de este proyecto, es el funcionamiento normal de Claude como servicio.

A note on where each piece of data lives, relevant to anyone asking from an IT perspective: the channel between the MCP server and the bridge — the one reading and modifying the Machine Expert project — is 100% local, on the same machine, without leaving to any external network. What does happen, as with any use of Claude, is that the conversation with the model (including user requests and tool return values) travels to Anthropic's infrastructure so Claude can reason about it and respond — this is not a peculiarity of this project, but the normal functioning of Claude as a service.

Rigor y validación

Rigor and Validation

Un servidor de este tipo puede tener two clases de errores muy distintas, y conviene distinguirlas: errores de lógica propia (código mal escrito, casos no contemplados, formatos de respuesta inconsistentes) y errores de suposición sobre cómo se comporta realmente Machine Expert (algo que la documentación oficial afirma, o que se ha observado una vez, pero que podría no ser universalmente cierto). Ninguna de las dos se detecta con el mismo tipo de prueba, así que este proyecto usa dos:

A server of this type can have two very different classes of errors, and it is worth distinguishing them: internal logic errors (badly written code, unhandled cases, inconsistent response formats) and assumption errors about how Machine Expert actually behaves (something official documentation states, or observed once, but which might not be universally true). Neither is detected with the same type of test, so this project uses two:

  • Una suite de tests automatizados (662 casos, ejecutados en segundos) confirma que el código en sí es internamente coherente: que cada herramienta devuelve el formato de datos que promete, que rechaza correctamente lo que debe rechazar, que las conversiones de datos (nombres, rutas, tipos) hacen exactamente lo que su contrato dice. Se ejecutan contra una simulación de Machine Expert, no contra el programa real.
  • Un plan de validación en vivo, ejecutado contra una instalación real de Machine Expert, confirma lo que ningún test automatizado puede confirmar por definición: que la propia plataforma se comporta como se ha documentado que se comporta.
  • An automated test suite (662 cases, executed in seconds) confirms the code itself is internally coherent: that each tool returns the data format it promises, correctly rejects what it should reject, and that data conversions (names, paths, types) do exactly what their contract says. They run against a Machine Expert simulation, not the real program.
  • A live validation plan, executed against a real Machine Expert installation, confirms what no automated test can confirm by definition: that the platform itself behaves as documented.

3. Campo de aplicación: una elección deliberada

3. Field of Application: A Deliberate Choice

El catálogo del capítulo anterior no se diseñó para cualquier tarea de automatización — tiene un objetivo muy concreto. Ese objetivo es PacDrive3, uno de los controladores de motion control de más alta gama del catálogo, y en particular su Template Full Programming Framework: la base de programación con la que se desarrollan sus proyectos.

The catalog in the previous chapter was not designed for just any automation task — it has a very specific objective. That objective is PacDrive3, one of the highest-end motion control controllers in our catalog, and in particular its Template Full Programming Framework: the programming base with which its projects are developed.

Vale la pena explicar qué es esto para quien no trabaje con PacDrive3 habitualmente. Un "template" de programación no es un simple punto de partida vacío — es una estructura completa, ya organizada, con cientos de combinaciones posibles de módulos, ejes y opciones de configuración, pensada para adaptarse a cualquier máquina que se quiera construir sobre ella. Esa misma flexibilidad, que es lo que hace a PacDrive3 tan potente, es también lo que hace que dominarlo lleve tiempo: cada ingeniero que se incorpora a un proyecto PacDrive3 necesita una inversión real para interiorizar esa estructura antes de ser productivo con ella — un coste que dentro de OEM Solutions conocemos bien.

It is worth explaining what this is for anyone who does not work with PacDrive3 regularly. A programming "template" is not a simple empty starting point — it is a complete, already organized structure, with hundreds of possible combinations of modules, axes, and configuration options, designed to adapt to any machine you want to build on top of it. That same flexibility, which makes PacDrive3 so powerful, is also what makes mastering it take time: every engineer joining a PacDrive3 project needs a real investment to internalize that structure before being productive with it — a cost we know well within OEM Solutions.

Este documento parte de una premisa simple: si una IA puede aportar valor real en ingeniería, el sitio para comprobarlo no es la tarea más fácil del catálogo, sino la más exigente. Automatizar algo sencillo demuestra que una herramienta funciona; automatizar algo que ya es conocido internamente como complejo demuestra además que la decisión de dónde aplicarla fue deliberada — un objetivo concreto, no un experimento genérico buscando cualquier caso de uso.

This document starts from a simple premise: if an AI can bring real value in engineering, the place to test it is not the easiest task in the catalog, but the most demanding one. Automating something simple proves a tool works; automating something internally known as complex also proves the decision of where to apply it was deliberate — a concrete objective, not a generic experiment looking for any use case.

Esa lógica explica, por ejemplo, por qué una parte importante del catálogo se concentra en el bus SERCOS: los dispositivos que cuelgan de él —servodrives, cabeceras de E/S remota— tienen una estructura especialmente rica, con módulos hijos y nietos, la posibilidad de cambiar de modelo sin perder la configuración, de mapear sus entradas y salidas, de parametrizarse de formas muy distintas. Cada una de esas operaciones concretas se presta bien a convertirse en una herramienta propia, y de ahí las 26 que cubren Lexium/ILM, TM5 y EdgeIO. Pero el verdadero potencial del proyecto no está solo ahí: está en la capacidad de leer, interpretar, crear y modificar código — programas, bloques de función y sus acciones, métodos y propiedades, los POUs del capítulo anterior —, así como instanciar variables y bloques de función dentro de ese mismo código. Es esa combinación, y no un único dominio, la que permite operar sobre el template completo.

This logic explains, for example, why an important part of the catalog is concentrated on the SERCOS bus: the devices hanging off it — servo drives, remote I/O heads — have a particularly rich structure, with child and grandchild modules, the ability to change models without losing configuration, map inputs and outputs, and parameterize in very different ways. Each of these concrete operations lends itself well to becoming a tool of its own, hence the 26 covering Lexium/ILM, TM5, and EdgeIO. But the true potential of the project is not just there: it is in the ability to read, interpret, create, and modify code — programs, function blocks and their actions, methods and properties, the POUs from the previous chapter —, as well as instantiate variables and function blocks within that same code. It is that combination, and not a single domain, that allows operating on the complete template.

No es un chatbot aparte que opina sobre el proyecto: es la IA operando el propio software desde dentro, con la misma ventana de Machine Expert abierta y visible que usaría cualquier ingeniero.

The result, as described in chapter 1, is a bridge between Claude and EcoStruxure Machine Expert built via MCP — an open standard, not exclusive to Claude, allowing connection of an LLM to a real work tool not originally designed for that. It is not a separate chatbot opining on the project: it is the AI operating the software itself from within, with the same open and visible Machine Expert window any engineer would use.

4. Dos historias reales: cuando la plataforma calla, el sistema avisa

4. Two Real Stories: When the Platform is Silent, the System Warns

Caso 1: Convertir un servodrive de tipo sin perder su configuración
Case 1: Converting a Servo Drive Type Without Losing Configuration

Nació de un incidente real: tras crear un servodrive y empezar a configurarlo, me di cuenta de que había elegido el modelo equivocado — un Lexium LXM62 en lugar del LXM52 que necesitaba. En vez de borrarlo y volver a crearlo y parametrizarlo desde cero, la pregunta que surgió fue directa: ¿puede cambiarse el tipo de un dispositivo ya creado sin perder la configuración que ya tiene?

It stemmed from a real incident: after creating a servo drive and starting to configure it, I realized I had chosen the wrong model — a Lexium LXM62 instead of the LXM52 I needed. Instead of deleting it and recreating and parameterizing it from scratch, the question that arose was direct: can the type of an already created device be changed without losing the configuration it already has?

La respuesta es sí, y la propia Machine Expert o permite mediante la misma función que usa su menú "Convert Device". Pero la investigación reveló algo que Machine Expert no comunica de forma fiable: si el servodrive tiene módulos hijo incompatibles con el nuevo tipo, se eliminan en silencio durante la conversión — sin excepción, y sin el aviso que la propia interfaz gráfica sí muestra en ese mismo caso.

The answer is yes, and Machine Expert itself allows it via the same function its "Convert Device" menu uses. But research revealed something Machine Expert does not reliably communicate: if the servo drive has child modules incompatible with the new type, they are deleted silently during conversion — without exception, and without the warning the graphical interface itself shows in that same case.

✓ La herramienta construida compara el estado del dispositivo antes y después de convertir, y reporta explícitamente qué módulos se han perdido. Es una protección que ni la plataforma original ofrece de forma consistente.

✓ The built tool compares the device state before and after converting, and explicitly reports which modules were lost. It is a protection that neither original platform offers consistently.

Caso 2: Reordenar módulos de E/S remota sin perder ninguno por el camino
Case 2: Reordering Remote I/O Modules Without Losing Any Along the Way

Una cabecera de E/S remota EdgeIO exige que su primer módulo sea siempre uno de alimentación — es una regla de la propia plataforma. Al investigar cómo reordenar los módulos de esa cabecera, apareció un caso concreto: si se intenta sacar el módulo de alimentación de su posición inicial, Machine Expert puede eliminarlo por completo, sin ninguna excepción ni aviso.

An EdgeIO remote I/O head requires its first module to always be a power supply one — it's a platform rule.
